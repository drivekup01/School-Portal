# School calendar

Source of truth is the supplied academic Google Sheet, tab `2/69` (gid `2064621928`). The fixed CSV export URL is fetched read-only from the backend; the source workbook is never modified. Thai displayed dates are parsed as Buddhist years, including same-month and cross-month/year ranges. Missing dates remain in an undated group. Unrecognized dates are shown for review rather than guessed or inherited from a preceding row.

`schoolCalendar` reads and refreshes a private Firestore snapshot on demand with a four-minute cache TTL (shorter than the five-minute browser poll to prevent an early poll skipping a full cycle) and a transaction lease. The UI rechecks while visible every five minutes and on returning to the page. Admin/full academic refresh is limited to once per 30 seconds. Fetch timeouts, size limits and layout checks retain the last successful snapshot with a warning, so a temporary source outage cannot erase the calendar or pins.

The staff/admin academic menus open `calendar/?mode=staff`. All active school personnel can read the full source calendar. Only administrator and academic #1/full can pin or unpin, with a fresh role check and optimistic pin revision inside the write transaction. Administrators can independently select events as homepage announcements through the homepage editor. Activity pins and announcement selections preserve each other and use the same revision guard. Read-only public views expose only explicitly pinned activities or selected announcements; no source-editor identity, pin revisions, unselected event details or direct source link are returned publicly. Pending events can be pinned and move onto the correct calendar date when the Sheet is filled in.

Homepage cards show up to three pinned activities (current/upcoming, undated, then recent past), with a link to the full pinned calendar. Every event opens its full details and responsible party. Events spanning a date range appear on every inclusive calendar day. A calendar month is a date display, not an attendance or SGS policy; this source does not automatically change attendance dates, semester settings, or grades.

IDs derive from source, normalized heading/responsible party and occurrence among identical entries, so date edits and unrelated inserted rows keep pins. Rewriting a heading/responsible party may create a new item that requires pinning again. CSV row text is treated as untrusted display data and rendered using textContent. Source URL cannot be supplied by a client. New Firestore collections `school_calendar_sources`, `school_calendar_pins`, and `school_calendar_audit` are server-only under existing default-deny rules and included in homepage backups.

Deployment adds no automatic pin selections. Pinning explicitly publishes that event to the public homepage. Calendar pin changes are included in the existing usage audit.

The homepage editor also supports banner, public school information, a manually maintained public staff directory, news, manual announcements and contact details. These use the existing private draft and explicit publish workflow. Calendar selections take effect immediately and are labelled separately from draft publishing. No private account directory is exposed. The homepage footer contains only the centered school logo and name.

The administrator staff editor can import a minimal name/position/department projection from the current timetable teacher roster. Importing adds missing people without overwriting manually edited profiles; it does not expose account emails or change login permissions. JPG/PNG/WebP uploads are resized and converted to bounded WebP images (preserving transparency) in the browser, checked by the admin-only backend, and stored under `homepage/staff/` in the existing private storage bucket. An unlisted UUID image endpoint serves only those JPEG/WebP images. Images and profile edits appear in the public directory when the homepage draft is published.

Public staff profiles now have an editable directory category: director, deputy, division, subject, or staff. The graphic directory groups these in that order and creates division/subject panels from the entered department name. There are no per-group slot limits; cards wrap responsively. Existing profiles infer a category until explicitly assigned, and legacy clients cannot erase an existing manual category. Photos are optional and show a designed placeholder until uploaded.

Staff profiles can mark `isHead` for a highlighted subject-group leader. Leaders sort before other members and render in a larger card with a textual badge. `groupColor` uses a validated palette; changing it in the editor applies to all current members of the same category and department. Automatic colours remain stable during search. Both fields default for legacy content and are preserved when an older editor omits them.

The board layout anchors the director in the top centre at a larger size, flanked by the first two deputies; additional administrators flow to extra rows. Administration and subject groups occupy responsive multi-column panels. Each panel independently grows in height as members wrap into new rows, with a larger leader card above members. The same leader flag can highlight a division head. Decorative art is independent of roster length.
