# ประวัติการใช้งาน

เปิดจากผู้ดูแลระบบ → ประวัติการใช้งาน เก็บเฉพาะเวลาเริ่มใช้งาน/เข้าสู่ระบบ ออกจากระบบจริง และผลการเพิ่มหรือแก้ไขข้อมูล ไม่เก็บการเปิดหน้า เมนู การคลิกปุ่มทั่วไป รหัสผ่าน โทเคน เนื้อหาเอกสาร หรือข้อความส่วนตัวของนักเรียน

ประวัติเริ่มสะสมตั้งแต่เปิดใช้ ไม่มีการสร้างประวัติย้อนหลัง ผู้ดูแลกรองวันที่และค้นหาในรายการที่โหลดได้ ครั้งละ 100 รายการ พร้อมโหลดรายการก่อนหน้า เวลาแสดงตามประเทศไทย การปิดแท็บหรือเบราว์เซอร์อย่างเดียวไม่ถือว่าออกจากระบบ

## โครงสร้าง

- `shared/usage-tracker.js` บันทึกเริ่ม session และการ sign-out ที่ Firebase SDK ยืนยัน ไม่บันทึกการเปิดหน้า โหมดทดลองไม่สร้างประวัติ
- `functions/usage-audit.js` ต้นฉบับกลาง คัดลอกไป codebase ของ School-OS, School-Budget และ School-Attendance เมื่อแก้ไข ใช้ wrapper รอบ callable เดิมโดยไม่แก้สิทธิ์หรือ payload ทางธุรกิจ บันทึกเฉพาะวิธีที่เปลี่ยนข้อมูล
- `schoolUsage` รับบันทึก session ของเจ้าของ token เท่านั้น และให้ผู้ดูแลที่ยัง active อ่านประวัติรวมได้ ไม่เปิดให้แก้ไขหรือลบประวัติ
- `school_usage_events` เป็น metadata แบบเพิ่มอย่างเดียว ผ่าน Admin SDK ไม่มีการเพิ่ม client rules โดย `school_usage_limits` จำกัดความถี่การรายงานจาก browser และ event ID ป้องกันการบันทึกซ้ำจากหลาย iframe
- `School-Attendance/functions/usage-marks.js` บันทึกการเปลี่ยนเช็กชื่อรายคาบของครูจาก immutable history ที่ฐานข้อมูลยืนยันแล้ว เพราะเส้นทางนี้ไม่ได้ผ่าน callable เหมือนผู้ดูแล ใช้รหัสจาก path เดิมเพื่อรองรับ trigger retry โดยไม่เพิ่มซ้ำ
- การเก็บประวัติ callable เป็น best effort หลังทราบผล ไม่เปลี่ยนผลสำเร็จทางธุรกิจเป็นความผิดพลาดเมื่อระบบบันทึกประวัติขัดข้อง และไม่เรียก mutation ซ้ำ การส่งเหตุการณ์เข้า/ออกจาก browser อาจไม่ถึงหากปิดโปรแกรมทันทีหรือไม่มีอินเทอร์เน็ต

## ตรวจสอบ

`node --test functions/test/*.test.js` ตรวจสิทธิ์ผู้ดูแล การปฏิเสธปลอม UID การตัดข้อมูลลับออก ผลสำเร็จ/ไม่สำเร็จ และไม่เก็บ read-only calls ส่วน trigger มี `School-Attendance/functions/test/usage-marks.test.cjs`
