# เกียรติบัตร / ผลงาน

## ทางเข้า

- ครูและผู้ดูแล: ดูแลนักเรียน → **เกียรติบัตร / ผลงาน** สำหรับค้นหา/อ่าน/ดาวน์โหลด และ **อัปโหลดเกียรติบัตร / ผลงาน** สำหรับจัดการ เป็นคนละเมนู
- นักเรียน: เมนู **เกียรติบัตร / ผลงาน** ในระบบนักเรียน ใช้บัญชีเดิม เลือกหัวข้อ ค้นชื่อ หรือเปิด PDF แล้วเลื่อนดู ไม่ได้แยกเอกสารไปผูกกับนักเรียนแต่ละคน

## อัปโหลด

เลือกหรือสร้างหัวข้อ ระบุชื่อไฟล์และประเภท เกียรติบัตร/ผลงาน เลือก PDF สูงสุด **25 MB / 200 หน้า** ระบบอ่านข้อความรายหน้าและเสนอชื่อเมื่อพบคำนำหน้าชื่อ ครูตรวจและแก้ชื่อสำหรับค้นหาได้ หากเป็นภาพสแกนที่ไม่มี text layer ให้ใส่ชื่อในช่องรายหน้าเองเพื่อให้ค้นหาเจอ หรือเว้นไว้แล้วให้ผู้ใช้เลื่อนดูภาพ

อัปโหลดสำเร็จแล้วเผยแพร่ให้นักเรียนในระบบได้ทันที แสดงชื่อผู้สร้างหัวข้อ ครูผู้อัปโหลด และผู้แก้ไขล่าสุด ไม่มี OCR หรือการนำชื่อไปผูกกับบัญชีนักเรียนอัตโนมัติ

ครูทุกบทบาทบุคลากรที่โรงเรียนอนุมัติสามารถอัปโหลดได้ แก้ชื่อไฟล์ ประเภท ชื่อรายหน้า เปลี่ยน PDF และลบได้เฉพาะไฟล์ของตนเอง ผู้ดูแลทำได้ทุกไฟล์ ชื่อเจ้าของไฟล์เดิมคงอยู่เมื่อผู้ดูแลแก้ไข หัวข้อที่มีไฟล์ครูคนอื่นอยู่ต้องให้ผู้ดูแลเป็นผู้ลบ

## เปิดดูและดาวน์โหลด

ค้นข้อความ/ชื่อภายในหัวข้อ ผลค้นหาแยกเป็นรายหน้า เปิดตรงหน้าที่พบได้ ตัวแสดง PDF.js แสดงหน้าเต็มแบบเลื่อนต่อเนื่อง ย่อ/ขยาย เลือกหน้า เต็มจอ ดาวน์โหลดทั้ง PDF หรือ **ดาวน์โหลดหน้านี้** ซึ่งสร้าง PDF หน้าเดียวบนเบราว์เซอร์ด้วย pdf-lib ไม่แก้ไฟล์ต้นฉบับ

PDF ภาพสแกนยังเปิดอ่านได้แม้ไม่มีข้อความค้นหา ตัวแสดงเป็นภาพ canvas และโหลดวาดเฉพาะหน้าที่ใกล้หน้าจอ เพื่อลดหน่วยความจำ

## ระบบและสิทธิ์

- ใช้ callable `schoolShowcase` ใน Firebase project `school-budget-3e69d`, codebase `school-portal`, region asia-southeast1
- ข้อมูลใน `school_showcase_topics`, `school_showcase_topic_names`, `school_showcase_files`, `school_showcase_uploads`, `school_showcase_audit` ผ่าน Admin SDK เท่านั้น ภายใต้กฎ default deny เดิม ไม่มี public URL สำหรับไฟล์
- PDF อยู่ bucket `school-budget-3e69d-student-reports` prefix `showcase/files/` อัปโหลดครั้งละ 1 MB ผ่าน callable และตรวจ PDF จริงที่เซิร์ฟเวอร์ก่อนเผยแพร่ ส่วนอัปโหลดชั่วคราวอยู่ `showcase/uploads/` และลบหลังเผยแพร่สำเร็จ งานที่ไม่เสร็จหมดอายุหลังหนึ่งชั่วโมง
- ตรวจบัญชี Google ของบุคลากร หรือบัญชีนักเรียนเดิม ตรวจเจ้าของและ revision สดใน transaction สำหรับการแก้/ลบ/เผยแพร่ นักเรียนเรียกคำสั่งเขียนไม่ได้ ไม่อนุญาตให้เลือก storage path เอง
- การลบซ่อนจากผู้ใช้และปิดการดาวน์โหลด เก็บไฟล์และ audit สำหรับตรวจสอบ ไม่ทำลายข้อมูลถาวร ผู้ใช้ที่ดาวน์โหลดไปก่อนหน้านี้แล้วจะยังมีสำเนาของตนเอง
- การสำรองข้อมูลเดิมยังไม่ได้รวมชุดนี้ ควรเก็บ PDF ต้นฉบับตามกระบวนการโรงเรียน ข้อมูลใหม่ไม่ถูกส่งเข้ากลุ่ม Telegram อัตโนมัติ

## ตรวจสอบ

`node --test functions/test/showcase.test.js`

ทดสอบสิทธิ์ อัปโหลดแบ่งส่วน ค้นรายหน้า แก้/ลบเฉพาะเจ้าของ ผู้ดูแลจัดการข้ามเจ้าของ คำขอซ้ำ ไฟล์เปลี่ยนและการถอนสิทธิ์ รวม parser PDF จริง ทดสอบในเบราว์เซอร์ด้วย PDF ตัวอย่าง 14 หน้า: ขยาย เปลี่ยนหน้า และดาวน์โหลดหน้าเดียว ตรวจแล้วว่าไฟล์ที่โหลดมีหนึ่งหน้าจริง ไม่มีการอัปโหลดข้อมูลนักเรียนจริงในการทดสอบ

เผยแพร่:
`firebase deploy --only functions:school-portal:schoolShowcase,functions:school-portal:schoolUsage --project school-budget-3e69d`

Frontend เผยแพร่จาก main ผ่าน GitHub Pages ตามเดิม PDF.js 4.10.38 และ pdf-lib 1.17.1 รวม license ไว้ใน vendor และโหลดตัวอ่าน PDF เมื่อเปิดเอกสารเท่านั้น
